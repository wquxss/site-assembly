# Integrate the runtime

The [static starter](../assets/starter/index.html) shows the required markup and works over HTTP without a build step. Reuse the runtime and adapt the markup to the target. The sample initializes once per document. For a framework route that can unmount, initialize after mount and add teardown for document and window listeners, observers, animation frames, active animations, and root tour attributes. Check that navigating away and back restores the normal page and starts at most one tour. Scope styles to the route or layout that owns the tour.

For a third-party page, apply the runtime directly in the browser on the real URL. Inspect the live DOM and write a small adapter that waits for the page to render, marks its existing elements, and mounts the tour control. The [overlay builder](../assets/browser-overlay/build-overlay.cjs) packages an adapter and optional CSS into an unpacked Chromium extension. Run `node build-overlay.cjs <URL> <adapter.js> <output-folder> [adapter.css]`. Initialize with `initAgentBuild(mediaQuery, { fitEnd: false })` to preserve the native page height and assemble all visible pending work at its scroll limit. Scope the extension to the requested page, leave native app scripts and requests untouched, and verify the overlay on the actual origin. For a client-routed app, restore the page and clear markers on route changes, and support re-entry or state the reload requirement. Test commerce UI without submitting payments, collecting user data, or connecting a wallet.

| File | Purpose |
| --- | --- |
| `agent-tour.js` | Actual document scroll, work-area stops, sticky-header offset, pause and replay |
| `agent-build.js` and `agent-build.css` | Job queue, cursor movement, text and image reveals |
| `main.js` | Static integration example, including reduced-motion changes |

- Give each main section root `data-tour-section="services"` or another readable name. Mark permanent site chrome with `data-tour-persistent` and keep it out of the job queue. The runtime accounts for the height of fixed and sticky headers. Keep the control outside any animated target. A deep link should open its original anchor and allow a manual start.
- Verify that each section boundary comes to rest just under the persistent header before its jobs start. The final section can grow to fill the usable viewport while keeping its native background. In a long section, align intermediate stops with the next unfinished target and clear completed elements from the viewport during the scroll. Check that pausing and finishing restore all completed elements.
- Tag independent elements with `data-tour-job="copy"`, `"design"`, or `"dev"`. Use one job per meaningful, self-contained block and avoid nested jobs. Use `data-tour-order` when the attention order differs from DOM order. Group horizontally scrolling cards into one track job. The runtime queues jobs that fit in the current viewport and also handles oversized jobs when their top reaches the header.
- Include the tour button and its label element. Localize labels and cursor names. Preserve the target site's markup, layout, palette, copy, imagery and navigation. Leave decorative backgrounds up during scroll. Use the sample only to verify the runtime.
- Disable cookie notices, demo badges, promotional popups, and unrelated floating widgets at their entry points in the isolated preview so they never cover the page or capture focus. Leave optional tracking disabled, and preserve policy links and any consent controls needed by forms. Check a fresh session and navigate to a secondary page to verify the overlays stay absent.
- Keep HTML readable by default. The runtime temporarily marks pending jobs at startup and clears these markers and active effects when it stops. Check existing motion for transforms or opacity on the same job. If necessary, reconcile those styles on active or completed jobs only. Use an iframe only where the target supports and authorizes embedding. Cross-origin frames cannot be staged by this page's scripts.
- Verify the typewriter effect on headings, paragraphs with multiple lines, and copy with inline markup. The runtime reveals graphemes using ranges over existing text and clears the ranges on pause or finish. Browsers without the CSS Highlight API use a stepped visual reveal.
- Check cursor continuity across work waves and scrolling. A cursor stays visible from its initial appearance until the final group fade. Idle agents move to the edges and new work begins at their current positions. Manual interruption clears the overlay for normal browsing.

Serve the result with the project's existing dev server or a local static server. Exercise the installed preview entry point and real content, including a browser reload with current assets. For the reference timings, see the defaults in `agent-tour.js` and `agent-build.js`.
