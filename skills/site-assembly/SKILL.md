# Site Assembly

Use this skill directly as `$site-assembly <URL>`. Take the URL from the user's message. Deliver a browser preview of nine simulated AI agents assembling the actual page as it scrolls. Preserve the site's content, design, navigation, imagery, and functionality. Add only the cursor visualization and tour control.

1. Open the URL, inspect desktop and mobile, and look for matching editable source. Use its normal entry point when a verified local checkout exists. Use public files for a local integration only when their provenance and reuse authorization are established and the original visual result can be verified. For a third-party page without suitable source, apply a browser-only overlay to the live page. Do not build an approximate replacement or reconstruct a proprietary interface. If an exact overlay cannot run, report the specific limitation. Publishing requires authorized access and a confirmed publishing request.
2. Preserve the page's native navigation, policy links, consent controls and essential functions. In a local preview, omit preview badges, promotional popups and unrelated widgets and disable optional tracking. On a live page, scope visual masking to the tour, keep native consent and transaction flows in place, and exclude unrelated popups from the animation. Use existing sections as scroll landmarks.
3. Reuse the runtime in [assets/starter](assets/starter). Read [references/integration.md](references/integration.md) before adapting it. Tag actual site elements as assembly targets. The sample HTML is a runtime test fixture. Agents are browser-simulated cursor roles. The build requires no model calls or server agent orchestration.
4. Animate in place on the real page:
   - Keep the site's backgrounds, imagery behind the content, and fixed or sticky navigation visible while browsing and scrolling. Use brisk, eased document scrolling. At each transition, align the new section directly below the fixed header or against the top of the viewport. Start its agent jobs after arrival. Within long sections, aim the next stop at the first unfinished element and fade out completed work as the page advances inside that section. Restore all content for manual browsing and after the tour. Let a short final section fill the remaining viewport so it can reach the same alignment.
   - Give the nine cursors distinct names, stable colors and reusable positions. Fade the group in once at the start and out once at the finish. Keep individuals visible between tasks and through scrolling. Let idle agents drift toward the viewport edges so later flights start from their actual positions. Stagger the work in overlapping waves and ease the flights and component reveals with gradual acceleration and braking. Type copy one character at a time in its original layout, open images from a corner, and place controls with a vertical reveal. Keep the overlay lightweight and free of docks, signatures, and scene covers.
   - Schedule all visible component jobs. Reuse agents when there are more than nine jobs. Tag content at a meaningful component level so paragraphs, images, cards, controls, and the footer all have a chance to assemble. Finish each visible queue before scrolling on.
5. Test the complete route from a fresh, pasted URL on desktop and narrow mobile. Check a sequence of intermediate scroll offsets, the original backgrounds throughout the route, fixed-header visibility, and actual completion of every reachable tagged job. Exercise manual interruption, replay, direct anchors, reduced motion, and readable content on JavaScript failure. User input can pause the tour and restore manual scrolling.

Return the working preview or the live URL with the scoped overlay and its activation instructions. State which mode was verified and whether anything was published.
